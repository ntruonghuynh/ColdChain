# Monitoring API (Milestone 3)

The interactive reference (request and response schemas, try-it-out) is generated by FastAPI at
**http://localhost:3000/api/docs** (OpenAPI JSON: `/api/openapi.json`). This page summarizes the
Milestone 3 endpoints and their rules. Conventions are unchanged from M1: success
`{"data": ..., "meta": ...}`, lists `{"data": [...], "meta": {"total", "limit", "offset"}}`, errors
`{"error": {"code", "message", "details", "request_id"}}`. All timestamps are UTC ISO 8601. All data is
simulated. No endpoint exposes simulator ground truth (guarded by `backend/tests/test_ground_truth_boundary.py`).

Specification: [M3 detector contract](../design/m3-baseline-detector-contract.md).

## Ingestion

| Method and path | Purpose | Notes |
|---|---|---|
| `POST /api/ingest/batches` | Ingest one batch of readings and context records (live) | Body: `business_ref`, `shipment_id`, `readings[]` (`sensor_id`, `event_at`, `temperature_c`), `context_records[]` (`sensor_id`, `event_at`, `door_state`, `battery_level_pct`, `ambient_temperature_c`). **`received_at` is set by the server**; sending it is refused (422 at batch level, `UNEXPECTED_FIELD` per record). Numbers are parsed as exact decimals: more than 2 decimal places is rejected (`PRECISION_EXCEEDED`), never rounded. Records are validated one by one (FR-01, BR-08, U-03, U-05); rejected records are stored with reason and raw payload. Identical duplicates are ignored (`DUPLICATE_IGNORED`, BR-07); conflicting ones are rejected (`DUPLICATE_CONFLICT` / `CONTEXT_CONFLICT`) and kept for review. **201** new batch; **200** same `business_ref` and payload (original result, BR-13); **409** same `business_ref`, different payload; **404** unknown shipment |

Trusted replay with recorded receipt times is not available over HTTP. It runs only through the internal commands `python -m app.monitoring replay` and `demo-ocean` (C-09).

Per-record reason codes: `NOT_AN_OBJECT`, `MISSING_FIELD`, `UNEXPECTED_FIELD`, `INVALID_TYPE`, `INVALID_TIMESTAMP`, `NAIVE_TIMESTAMP`, `NOT_A_NUMBER`, `PRECISION_EXCEEDED`, `OUT_OF_PHYSICAL_RANGE` (temperature outside −40.00 to +60.00 °C, limits accepted), `OUT_OF_RANGE` (battery outside 0–100 %), `INVALID_VALUE`, `CLOCK_SKEW` (`event_at` more than 5 min after `received_at`), `SHIPMENT_MISMATCH`, `UNKNOWN_SENSOR`, `SENSOR_NOT_ASSIGNED`, `OUTSIDE_MONITORING_WINDOW`, `DUPLICATE_CONFLICT`, `CONTEXT_CONFLICT`, `CONTEXT_WITHOUT_READING`.

## Monitoring (read-only, causal `as_of`)

Endpoints with `as_of` show only readings received and results raised by that processing time (default now). Without a time zone `as_of` is refused (422).

| Method and path | Purpose |
|---|---|
| `GET /api/shipments/{id}/telemetry?as_of=` | Timeline per sensor: readings (`event_at`, `received_at`, `temperature_c`, `delivery_lag_s`, `temperature_state`), confirmed gaps, observed runs, monitoring status; policy and detector configuration references |
| `GET /api/shipments/{id}/monitoring?as_of=` | Monitoring state of each sensor: `CURRENT` (newest reading ≤ 7 min 30 s old), `STALE` (≤ 15 min), `UNKNOWN` (> 15 min; `provisional_review_threshold_reached` at ≥ 30 min), `NOT_STARTED`, `ENDED`. A state is never an incident |
| `GET /api/sensors/{sensor_id}/status?as_of=` | The same for one sensor on each shipment it is assigned to |
| `GET /api/shipments/{id}/deliveries` | Missing and delayed data: every received batch with event range, `max_delivery_lag_s`, `monitoring_state_before_receipt`, `unobserved_before_receipt_s`, `late_backfill` (the span it fills had reached the 30-min review value), `out_of_order`, `gap_revisions_superseded`; plus the full gap history |
| `GET /api/shipments/{id}/data-gaps?as_of=&include_superseded=` | Confirmed missing-reading gaps: `bracketing_span_s` / `_min` (exact time between the bounds, compared with the policy), `estimated_missing_samples`, `estimated_missing_duration_s` (information only), `gap_status` (`SHORT_GAP`, `UNKNOWN`, `UNKNOWN_REVIEW_REQUIRED`), bounds, `state` |
| `GET /api/shipments/{id}/detections?as_of=&meets_policy_duration=&include_superseded=` | Observed out-of-range runs (`direction`, first/last `event_at`, `observed_duration_s`, `threshold_min`, `meets_policy_duration`, `confirmed_event_at`, `evidence_received_at`, `peak_c`, adjacency to gaps) |
| `GET /api/shipments/{id}/warnings?as_of=&evidence_only=&include_superseded=` | Persisted data-quality warnings (`GAP_ADJACENT_OUT_OF_RANGE`, `MISSING_READINGS`, `READING_CONFLICT`, `CONTEXT_CONFLICT`), with `affects_quality_evidence` |
| `GET /api/monitoring/summary?as_of=` | Sensors by monitoring state, open incidents by category and by evidence basis, current warnings, ingestion totals, detector configuration |
| `GET /api/detector-configs` | Detector configuration versions (`DET-BASELINE v1.0.0`: nominal 300 s, continuity 450 s) |

## Incidents

| Method and path | Purpose |
|---|---|
| `GET /api/incidents?status=&category=&shipment_id=&limit=&offset=` | Incidents; with `status=OPEN` this is the **excursion queue** (FR-20). Each item has its latest revision (`extent_*`, `basis`, `gap_continuity_warning`, durations) and `review_state` (`PENDING_QUALITY_REVIEW` while open) |
| `GET /api/incidents/{incident_id}` | Detail: all revisions (append-only), evidence (readings around the extent, gap history, evidence warnings), policy and detector configuration references, opening evaluation (mode, trigger, `as_of`, input fingerprint), dispositions and decision reassessments (U-04) |

There is no endpoint that closes an incident, records a disposition or releases goods (Milestone 5). The detector never writes the incident status.
